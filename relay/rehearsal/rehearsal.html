Where signals go after your code writes them

The same request leaves three kinds of evidence, and each travels a different road to a different store. Connecting the dots means knowing these roads, and that the ids on each piece (trace id, request id) are what join them back together.

What goes wrong on the log road

  1. Stack traces split. A 40-line Java exception becomes 40 separate events unless the app logs JSON or the shipper is told how to join multiline records.
  2. Free text can't be filtered. "Payment failed for order 991" needs a regex; {"event":"payment_failed","order":991} needs a filter.
  3. No id, no join. Without a request id and trace id on each line, you can't go from a log line to its trace, or from a customer's complaint to the line.
  4. Logs are late. Shipping, parsing and indexing take seconds to minutes. Alert on metrics; use logs to explain.
  5. Lines get lost. A crash can drop what was still buffered; a shipper under pressure drops or delays; node log rotation can delete files before they're read.
  6. Cost grows with volume. Stores bill per GB ingested and per day kept. DEBUG in production, or a log line per request in a hot path, is often the biggest monitoring bill.
  7. Secrets and personal data leak in. Tokens, emails and payloads end up in a store many people can search. Redact in the app or the collector.
  8. Time disagrees. Time zones, clock skew between hosts, and "time logged" vs "time ingested" reorder events. Log UTC in ISO 8601.
  9. Fine in logs, fatal in metrics. A user id on a log line is normal; as a metric label it creates a series per user.

OpenTelemetry in one paragraph

OpenTelemetry is the open, vendor-neutral standard for producing telemetry. Each language has one API and SDK (or an auto-instrumentation agent) that creates traces, metrics and logs with the same names everywhere (semantic conventions) and the same context (trace id). Everything travels as OTLP to an OTel Collector, which can batch, sample, drop personal data and fan out to any backend. Changing vendors means changing the Collector's exporter, not the code.
